# Phase 2 开发方案

继续在 Phase 1 历史上开发；保留 final 与 final-initial 对象，结束时新增 p2。

1. 先观察原生 Outline，再实现独立 VSCode 扩展；提供真实截图与提供器测试。
2. 核心保留公开领域抽象、命令历史和四个扩展点。将内置图形和命令搬至插件包，由宿主装配。
3. 宿主统一事务式加载插件，代码装配与配置装配共用暂存、清单比较、重复检测和提交路径。
4. 分步增加 stats、dir（目录端口及 Node 适配器）、box、modified-star。box 通过两个独立提交证明 A/B 的差异约束。
5. 保留 Phase 1 测试，增加独立插件及加载器测试，并从 final 编译基线进行逐字节兼容性比较。
6. 用 Git 历史生成指标、架构对比、ADR 和验收材料；核对旧标签后新增 p2 并推送。

属性处理器优先于默认白名单；多个匹配者拒绝。set 在独立文档副本执行，失败不提交历史。
图形支持通用 validate 钩子；复合图形通过自身类保护必要子部件，不在内核写 box 分支。
dirty 选择保存内容比较，祖先传播开启；标签顺序按插件注册顺序。

本文件是开发起点，最后的实际接口、代码位置与修订以 doc/README.md 和 ADR 为准。
